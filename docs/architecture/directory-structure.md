# ディレクトリ構成

この文書では、プロジェクトの基本的なディレクトリ構成と、
各ディレクトリの責務を定義する。

ここで示す構成は、プロジェクトの成長を見据えた目標構成とする。

開発初期からすべてのディレクトリやファイルを作成する必要はなく、
コード量や責務の増加に応じて段階的に分割する。

ディレクトリを分割すること自体を目的とせず、
可読性や保守性が向上する場合に分割する。


## フロントエンド

フロントエンドの基本的なディレクトリ構成は以下とする。

```text
src/
├── pages/
├── components/
├── styles/
├── App.jsx
└── main.jsx
```

### pages

`pages`には、各画面を構成するReactコンポーネントを配置する。

画面単位のUIや、その画面固有の処理を記述する。

### components

`components`には、複数の画面で利用するUIや、
ページから分離することで責務が明確になるUIコンポーネントを配置する。

すべてのUIを細かくコンポーネント化する必要はなく、
再利用性や可読性を考慮して分離する。

### styles

CSSファイルは`styles`に配置する。

画面固有のスタイルが増えた場合は、
対応するページごとにCSSファイルを分ける。

コンポーネント固有のスタイルについても、
スタイルが複雑になった場合や分離することで可読性が向上する場合に、
個別のCSSファイルへ分ける。

Reactファイルと対応するCSSファイルを作成する場合は、
対応関係が分かりやすい命名とする。

例:

```text
pages/HomeView.jsx → styles/HomeView.css
```

複数のページやコンポーネントで共通して使用するスタイルは、
共通CSSファイルに記述する。

特定のページやコンポーネントでのみ使用するスタイルを
共通CSSへ記述することは避ける。

同じスタイルを複数のCSSファイルへ重複して記述することは避け、
共通化できる場合は共通CSSへまとめる。

## バックエンド

TauriのRustコードは、責務が増えた場合に
役割ごとにディレクトリを分割する。

目標とする基本的なディレクトリ構成は以下とする。

```text
src-tauri/
├── src/
│   ├── commands/
│   ├── services/
│   ├── repositories/
│   ├── models/
│   ├── database/
│   ├── errors/
│   ├── lib.rs
│   └── main.rs
│
├── migrations/
├── Cargo.toml
└── tauri.conf.json
```

開発初期から上記のディレクトリをすべて作成する必要はない。

コード量や責務が小さい場合はシンプルな構成を維持し、
責務の分離が必要になった段階で対応するディレクトリへ分割する。

### commands

`commands`には、ReactからTauriの`invoke`を通して呼び出される
Tauri Commandを配置する。

CommandはフロントエンドとRust側の処理を接続する入口として扱う。

処理が複雑になった場合は、
`services`や`repositories`へ責務を分離する。

### services

`services`には、アプリケーションの主要な処理や
ビジネスロジックを配置する。

Command内の処理が複雑になった場合や、
複数の処理を組み合わせる必要がある場合に分離する。

### repositories

`repositories`には、SQLiteへのデータアクセス処理を配置する。

データベース操作が増えた場合に、
データの取得、作成、更新、削除などの処理を
他の処理から分離するために使用する。

### models

`models`には、アプリケーション内で使用する
データ構造を定義する。

データ構造が増えた場合に、
関連する型や構造体をまとめて管理する。

### database

`database`には、SQLiteの接続や初期化など、
データベース全体に関する処理を配置する。

### errors

`errors`には、アプリケーション内で使用する
共通のエラー型やエラー処理を配置する。

エラー処理が単純な間は無理に分離せず、
共通化が必要になった段階で使用する。

### migrations

`migrations`には、SQLiteのテーブル作成や変更など、
データベーススキーマの変更を管理するファイルを配置する。

既存データが存在する状態でデータベーススキーマを変更する場合は、
既存データを失わないようにマイグレーションを行う。
