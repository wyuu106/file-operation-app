# テンプレート要件

## 1. ファイル名変更テンプレート

ユーザーはリネームルールをテンプレートとして保存できる。

テンプレートには最低限以下の情報を保存する。

- id
- name
- pattern
- created_at
- updated_at

テンプレートは以下の操作を行える。

- 作成
- 保存
- 一覧表示
- 編集
- 削除

---

## 2. テンプレートに使用できる要素

MVPでは以下の要素を使用できる。

| 表示名 | 内部変数 | 説明 |
|---|---|---|
| 元のファイル名 | `{original}` | 拡張子を除いた変更前のファイル名 |
| 会社名 | `{company}` | ファイルごとに入力された会社名 |
| 名前 | `{name}` | ファイルごとに入力された名前 |
| 日付 | `{date}` | プレビュー生成時の日付 |
| 連番 | `{number}` | ファイルの選択順に基づく連番 |
| 固定文字 | - | テンプレート作成時にユーザーが入力した文字列 |

内部変数はテンプレートの保存および
ファイル名生成処理で使用する。

内部変数はユーザーには表示せず、
ユーザーは「ファイル名」「会社名」「名前」「日付」「連番」などの
表示名を使用してテンプレートを作成する。

---

### ファイル名

元ファイル名を使用する。

拡張子を除いた値を使用する。

例:

```text
invoice_001.pdf
↓
invoice_001
```

---

### 会社名

リネーム対象ごとにユーザーが事前に入力した会社名を使用する。

例:

```text
A社
```

生成するファイル名では会社名を
`【A社】` のように【】で囲む。
入力時に【】を付けた場合も二重にはしない。
会社名の直後には区切りの `_` を付けない。

会社名はファイル選択前に入力する。

複数の会社名を入力する場合は、それぞれに番号を付与する。

例:

```text
① A社
② B社
③ C社
```

ファイル選択後、この番号とファイルの選択番号を対応付ける。

---

### 名前

リネーム対象ごとにユーザーが事前に入力した名前を使用する。

例:

```text
太郎
```

生成するファイル名では名前の後に
「様」を自動で付ける（例: `太郎様`）。
入力時に「様」を付けた場合も二重にはしない。

名前は会社名と同様にファイル選択前に入力する。

会社名と名前は1つの組として管理する。

例:

```text
① A社 / 太郎
② B社 / 花子
③ C社 / 二郎
```

一度のリネーム操作で入力できる組は、
最大10件とする。

---

### 日付

リネーム実行に使用する日付。

Format:

```text
YYYY-MM-DD
```

例:

```text
2026-09-26
```

日付はプレビュー生成時点で確定する。

プレビュー生成後に日付が変わった場合でも、
プレビューで確定した日付を使用する。

---

### 連番

リネーム対象として選択されたファイルの
選択順に基づいて連番を付与する。

例:

```text
① C.pdf
② A.pdf
③ D.pdf
```

の場合、

```text
C.pdf → 001
A.pdf → 002
D.pdf → 003
```

とする。

連番は3桁のゼロ埋めとする。

```text
001
002
003
...
010
```

個別にファイルを選択した場合は、
ユーザーが選択した順番を使用する。

一括選択した場合は、
ファイル名の自然順（昇順）を選択順として使用する。

連番はプレビュー生成時に確定する。

プレビュー生成後は連番を再計算せず、
プレビューで確定したリネーム計画を使用する。

---

### 固定文字

ユーザーが指定した固定文字をファイル名に追加する。

例:

```text
請求書
```

---

## 3. テンプレート作成

テンプレートは文字列として直接入力するのではなく、
UI上で構成する。

ユーザーは使用したい要素を選択し、
並び順を設定できる。

例:

```text
会社名 → 名前 → 日付 → 固定文字
```

上記の設定から、

```text
【A社】太郎様_2026-09-26_請求書.pdf
```

のようなファイル名を生成する。

拡張子はテンプレートの構成要素として扱わず、
変更前のファイルの拡張子をそのまま引き継ぐ。

テンプレート作成画面では、
生成されるファイル名の例をリアルタイムで表示する。

テンプレートの内部表現は実装側で管理し、
ユーザーに内部的な変数名や記法を意識させない。
