# UI要件

## 1. 画面一覧

| 画面 | 説明 |
|---|---|
| ホーム | リネーム対象ファイルとテンプレートを選択する |
| プレビュー | リネーム後のファイル名を確認・編集し、リネームを実行する |
| テンプレート | テンプレートの作成・編集・削除を行う |
| 変更履歴 | ファイル名の変更履歴を確認する |

---

## 2. 画面遷移

画面下部にナビゲーションタブを配置し、
以下の画面を遷移できるようにする。

- ホーム
- テンプレート
- 変更履歴

プレビュー画面はホーム画面から遷移する。

プレビュー画面では画面下部のナビゲーションタブを表示せず、
リネーム作業に集中できる画面とする。

---

## 3. ホーム画面

ホーム画面では、以下の順序で操作を行う。

1. 使用するテンプレートの選択
2. テンプレートに応じたリネーム情報の入力
3. 対象フォルダの選択
4. 対象ファイルの選択
5. プレビュー画面への遷移

### テンプレート選択

ユーザーは最初に、
ファイル名変更に使用するテンプレートを選択する。

選択したテンプレートに含まれる要素に応じて、
その後に表示する入力項目を変更する。

### リネーム情報の入力

選択したテンプレートに「会社名」が含まれている場合は、
会社名の入力欄を表示する。

選択したテンプレートに「名前」が含まれている場合は、
名前の入力欄を表示する。

テンプレートに含まれていない項目の入力欄は表示しない。

例:

```text
テンプレート：会社名 → 名前 → 日付

① 会社名 [ A社 ]  名前 [ 太郎 ]
② 会社名 [ B社 ]  名前 [ 花子 ]
③ 会社名 [ C社 ]  名前 [ 二郎 ]

[ ＋ 追加 ]
```

「会社名」「名前」のいずれも使用しないテンプレートの場合は、
リネーム情報の入力欄自体を表示せず、
直接ファイル選択へ進める。

### ファイル選択

選択されたファイルには、
選択された順番を示す番号を表示する。

ファイルごとのリネーム情報が存在する場合、
その番号とファイルの選択番号を対応付ける。

例:

```text
入力情報                 選択ファイル

① A社 / 太郎      ↔      ① aaa.pdf
② B社 / 花子      ↔      ② bbb.pdf
③ C社 / 二郎      ↔      ③ ccc.pdf
```

ファイルごとのリネーム情報を使用する場合は、
入力件数と選択ファイル数が一致している場合のみ
プレビューへ進むことができる。

件数が一致していない状態で
プレビューへ進もうとした場合は、
ポップアップを表示して画面遷移を行わない。

表示例:

```text
入力した情報と選択したファイルの数が一致しません。

入力情報：3件
選択ファイル：2件

同じ数になるように設定してください。
```

### Undo

ホーム画面には、
直前のリネーム操作を元に戻すためのUndo機能を配置する。

ユーザーがUndoによってどの操作が取り消されるか確認できるように、
Undoボタン付近に最低限以下の情報を表示する。

- リネームを実行した日時
- 対象フォルダ
- 変更したファイル数

表示例:

```text
直前の変更

2026/09/26 14:30
請求書フォルダ
12ファイル

[ 変更を元に戻す ]
```

Undo可能な操作が存在しない場合は、
Undoボタンを無効化するか表示しない。

---

## 4. テンプレート画面

テンプレート画面では、
リネームに使用するテンプレートを管理する。

以下の操作を行える。

- テンプレートの作成
- テンプレートの編集
- テンプレートの削除

テンプレート作成・編集時には、
テンプレートを構成する要素とその並び順を
UI上で設定できるようにする。

生成されるファイル名の例をリアルタイムで表示する。

---

## 5. プレビュー画面

プレビュー画面では、
選択したテンプレートをもとに生成された
変更後のファイル名を確認する。

変更前と変更後のファイル名を
対応関係が分かる形で表示する。

変更後のファイル名は、
リネーム実行前にユーザーが個別に編集できる。

拡張子は表示するが、
ユーザーが編集できないようにする。

Validationエラーが存在する場合は、
対象ファイルとエラー理由を表示する。

問題が解消されるまで、
リネームを実行できない状態とする。

### プレビュー画面からの離脱

リネームを実行せずにプレビュー画面から別の画面へ遷移する場合は、
現在のプレビュー内容が破棄されることを確認する
確認ダイアログを表示する。

確認ダイアログには、以下のメッセージを表示する。

> 現在のプレビューは破棄されますが、画面を移動しますか？

ユーザーが遷移を選択した場合は、
現在のプレビュー内容を破棄して画面を移動する。

ユーザーがキャンセルした場合は、
画面遷移を行わず、現在のプレビュー画面を維持する。

プレビュー画面でユーザーが個別に編集した
変更後ファイル名についても、
プレビュー内容とともに破棄する。

リネームが正常に完了した後の画面遷移では、
この確認ダイアログを表示しない。

---

## 6. 変更履歴画面

変更履歴画面では、
過去に実行したファイル名変更の履歴を一覧で確認できる。

変更履歴には、
正常完了した操作だけでなく、
失敗した操作やロールバックが正常に完了しなかった操作も表示する。

履歴一覧では、最低限以下の情報を表示する。

- 実行日時
- 対象フォルダ
- 変更したファイル数
- 処理結果
- Undoの状態

処理結果では、最低限以下の状態を区別する。

- 正常完了
- 失敗（ロールバック完了）
- 要確認

Undoの状態は、
正常完了した操作について表示する。

ユーザーが履歴を選択すると、
その操作に含まれる各ファイルについて、
以下の情報を確認できる。

- 変更前ファイル名
- 変更後ファイル名
- 必要に応じて各ファイルの処理結果

変更履歴画面は履歴の確認のみを目的とし、
この画面からUndoを実行することはできない。
