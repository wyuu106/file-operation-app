# Rust File Operations

ファイル操作では安全性を最優先する。

## ファイル名変更フロー

一括リネームでは以下の流れを基本とする。

1. 対象ファイル取得
2. ユーザーがファイルを選択した順序を保持
3. リネーム計画生成
4. 有効性検証
5. プレビュー
6. ユーザーの確認
7. 実行直前の有効性検証
8. rename_operationをin_progressとして記録
9. 各ファイルをリネーム
10. 各ファイルの実行結果を追跡
11. 全成功した場合、operationをcompletedにする

途中で失敗した場合は、
それまでに成功したリネームを逆順にロールバックする。

ロールバックの結果も記録する。

ファイル操作とSQLiteトランザクションを
完全に一体化できるものとして扱ってはならない。

アプリケーションの異常終了によって
in_progressのoperationが残る可能性を考慮する。

起動時に未完了operationが存在する場合は、
DBの状態だけを信用せず、
実際のファイルシステムの状態と照合する。

## 検証

以下を確認する。

- ソースファイルが存在していること
- 移行先・出力先が衝突しないこと（destination does not conflict）
- 変更後のファイル名がユニークであること
- ファイル名が有効であること
- ソースと出力先が異なること（Source and destination differ）

既存ファイルを上書きしない。

## エラー処理

unwrap()に依存しない。

ユーザー操作によって発生し得るエラーは
Resultとして適切に処理する。

## Undo

リネーム前後のパスを記録する。

Undoでも通常のrenameと同様に
衝突チェックを行う。
